# Part 2 — Talent mapping & sourcing

The database contains 50 fictional profiles, five hypothetical vacancies and seven sector contexts. IDs begin FIC-; no names, email addresses or real personal profiles are included. Availability, experience and competency notes are simulated.

Fields include current title, industry, relevant experience, evidenced skills, explicit unknowns, market, methodology, enterprise exposure, transferable capabilities, availability and source category. Profile generation uses a reproducible seed; it creates varied scenarios, not a representative talent-market sample.

Search supports ID/title/industry/skill text; role, evidenced skills, minimum experience and market filters can be combined. Required skills use AND logic. Downloads contain the filtered fictional records. No real sourcing integration is connected.

Source category reflects a hypothetical origin. A technical capability contributes to matching only when a non-empty evidence note exists. Methodology/enterprise-exposure context alone does not establish proficiency. Synthetic notes are intentionally brief and must not be mistaken for validated candidate evidence.

Validation rejects duplicate IDs, non-fictional records, impossible experience values, conflicting evidenced/unknown skills and evidence assigned to undeclared skills. Extend the schema and validation before using richer records. Real candidate data is outside the authorised scope.

For real sourcing, begin with agreed competencies, company and market hypotheses; use authorised tools and consent-based engagement. Measure response quality and downstream progress rather than treating source volume as success.
